NADA NETWORK / TAKE-HOME ASSIGNMENT 
People & connections API 
Nada helps families discover marriage connections through the people a family already knows. Build a small HTTP API that stores people and their direct contacts, and answers how two people are connected. 
Due: Saturday, 10 October 2026, 9 pm IST 
Expected effort: an evening or two. 
Stack: Core Java 17 or newer; keep data in memory. Any build tool. Gson or Jackson is fine. Vert.x is optional. Neo4j is optional and earns no extra marks. 
01 POST /people 
Create a person. Assign the ID yourself. Return 201. 
Request: {"name": "Asha"} 
Response: {"id": 1, "name": "Asha"} 
02 POST /knows 
Create a mutual connection. Return 204. Sending the same connection again is not an error. 
Request: {"a": 1, "b": 2} 
03 GET /people/{id}/contacts 
Return 200 with direct contacts, or an empty list. 
Example: GET /people/1/contacts 
Response: [{"id": 2, "name": "Rohan"}] 
04 GET /path?from=1&to=5 
Return 200 with the shortest path of three hops or fewer. If several paths are equally short, return any one. If none qualifies, return {"connected": false}. 
{"connected": true, "hops": 2, "path": [ 
 {"id": 1, "name": "Asha"}, 
 {"id": 3, "name": "Meera"}, 
 {"id": 5, "name": "Kabir"} 
]}

Behaviour and validation 
Unknown person: return 404 with an error object such as {"error": "no person 9"} for an unknown ID of 9. 
Same start and end: for an existing person, return connected: true, hops: 0, and a path containing only that person. 
Bad request: return 400 for invalid JSON, a missing required body field, an empty or blank name, or a connection where a equals b. 
Path parameters: return 400 if from or to is missing or malformed. 
Names: accept text in any script, including Hindi, and return it exactly as it was supplied. Required test 
Include at least one test for the path endpoint covering both sides of the three-hop limit. In a simple chain with no shortcuts: 
A - B - C - D A to D: connected, 3 hops 
A - B - C - D - E A to E: not connected
